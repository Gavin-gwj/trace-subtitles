# Prototype Instructions

Run the local server yourself and open the preview in the in-app browser. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

## Selected Direction

- Reference: Cinema Trace concept, selected by the user.
- Page theme: locked dark cinematic theme. The hero uses a full-bleed still that reads as a real English-learning YouTube video, with creator-led studio photography rather than a film scene.
- Palette: charcoal black, warm ivory, muted film amber, pale mint for saved vocabulary. Do not introduce purple.
- Typography: warm display sans for the large headline, restrained grotesk for interface copy, and readable Chinese fallbacks.
- Motion: subtle cinematic reveals and a working subtitle/word-lookup interaction. Respect reduced-motion.
- Voice: plain Chinese product copy. Keep the English wordmark and realistic English subtitle examples.
- Product demo reference: the real Trace lookup card uses a white surface, black word heading, blue part-of-speech tag, sample-sentence translation, green saved state, and pale-green known state. Match that product anatomy in the hero while keeping the card floating over the video.
- Navigation behavior: the desktop header stays available while scrolling. It begins transparent over the hero, then contracts into a translucent dark pill with a fine border and blurred backdrop after the hero exits.
- Avoid adding fake testimonials, invented customer logos, fabricated usage metrics, or additional routes.
